

# リアルタイムチャットアプリ

**Prisma × NestJS × Next.js で構築した、保存もできるリアルタイムチャットアプリ**

> Next.js 15 × NestJS 11 × Socket.io × Prisma(SQLite)

---

## アプリの概要

このアプリは、WebSockets（Socket.io）を活用して、**「リロードしても消えない、かつ瞬時に届く」**リアルタイムチャットアプリです。

単なるチャット機能だけでなく、Prisma ORMを使用してデータベース（SQLite）と連携。ページを開いた瞬間に過去の履歴を復元する「初期化処理」を実装しており、実用的なメッセージツールとしての基礎を備えています。

### 開発の背景

これまで私は、**PHP/Larave**を中心にバックエンド開発を学んできました。Laravelは素晴らしいフレームワークですが、モダンな開発現場で主流となっている**TypeScript**をバックエンド（NestJS）でも使いこなせるようになりたい！と言う思いが今回の開発のきっかけです。

今まで作ってきたアプリは、10秒ごとに取得や画面リロードが基本でした。
しかしチャットのように **「誰かが送った瞬間に、自分の画面にもパッと現れる」**と言う双方向のような動きを実現したいと考え、**WebSocket**等言う技術に挑戦しました。

Laravelでの経験があったからこそ、今回の技術も「あ、これはLaravelで言うところのあの機能だな」と、知識をリンクさせながら開発することができました。

## こだわったポイント

### 1. 「自分か相手か」を直感的に判別するUI
- 自分自身のメッセージは右側に青い吹き出しで、他人のメッセージは左側にアバター付きのグレーの吹き出しで表示。LINEのように説明がなくても誰でも使える画面を目指しました。

### 2. リロードしても「自分」を忘れない記憶機能
- ログイン機能がない簡易構成でも、ブラウザの `localStorage` を活用することで、リロードしても入力した名前を保持。過去の自分の発言が他人のように扱われないよう、クライアントサイドで状態を維持する工夫をしました。

### 3. 日本語入力に配慮したUX設計
- 誤送信をブロック: 日本語を入力して「Enter」で確定する時、勝手に送信されないように制御しました。
- 改行も自由自在: Shift + Enter で改行できる、プロ仕様の入力欄を実装しました。

### 4. Prismaによるシンプルなデータ永続化
- 過去の会話も復元: メッセージを送るたびにデータベース（Prisma/SQLite）に保存されるため、あとから来た人もこれまでの会話を読むことができます。

## 主な機能

| 機能名 | 内容 |
|--------|------|
| リアルタイム通信 | Socket.ioにより、送信した瞬間に全ユーザーの画面へメッセージを配信 |
| メッセージ永続化 | Prisma + SQLiteを使用。送信と同時にDBへ保存し、サーバーを再起動してもデータが残る |
| 過去ログ自動読み込み | ページを開いた（接続した）瞬間に、過去の全メッセージを自動取得して表示 |
| 自分・他人の判別UI | 送信者名に基づき、吹き出しの向きと色、アバターの有無をリアルタイムに切り替え |
| 名前保持機能 | ブラウザのlocalStorageに名前を保存。再訪時も入力を省略可能 |
| メッセージ送信制御 | Enterでの改行に対応し、日本語変換確定後の誤送信を防止。送信ボタンでの明示的な送信 |

## セットアップ方法

### 前提条件
- Node.js 20以上
- npm

### 手順1：リポジトリをクローン
```bash
git clone git@github.com:ando625/chatApp.git
cd chatApp
```

### 手順2：バックエンドの設定
```bash
cd my-chat-app
npm install
```

#### .envファイルを作成（my-chat-app直下に）
```
DATABASE_URL="file:./dev.db"  # データベースURLを設定
```


```
npx prisma db push    # データベースの器を作成
```

```
npm run start:dev    #起動
```

### 手順3：フロントエンドの設定（別のターミナル）
```bash
cd frontend
npm install
npm run dev
```

## トラブルシューティング

### 1. `EADDRINUSE: address already in use :::3000` と表示される場合

このエラーは、Next.js（フロントエンド）と NestJS（バックエンド）が**同じ3000番ポートを奪い合っている**ために発生します。



#### 解決策：ポート番号の変更
バックエンドを `3001` 番に変更して、衝突を回避します。

1.  **バックエンドの修正**: `backend/src/main.ts` を開き、ポートを `3001` に変更。
    ```typescript
    await app.listen(3001);
    ```
2.  **フロントエンドの修正**: `frontend/src/app/page.tsx` の接続先を `3001` に変更。
    ```typescript
    const SOCKET_SERVER_URL = "http://localhost:3001";
    ```

#### それでも解決しない場合（プロセスの強制終了）
以前のプロセスが裏で動いたままになっている可能性があります。Macのターミナルで以下のコマンドを実行して、ポートを解放してください。

```bash
# 3000番を占有しているプロセスを探す
lsof -i :3000

# 表示されたPID（数字）を指定して強制終了
kill -9 [ここにPIDの数字を入れる]
```
